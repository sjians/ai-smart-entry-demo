# AI 智能录入 · 对话式 — POC Demo Agent

> 由交互原型 `AI_智能录入_独立交互原型.html` 100% 转化而来的**可运行、模块化、可测试**工程。
> 适合个人测试、内测、客户体验。

一个面向销售线索录入场景的「AI 智能录入」演示：用户可以**一句话说完**、**让 AI 一项项问**、**上传文档/图片 OCR**、**语音输入**、**批量导入**，AI 实时把自然语言解析成结构化线索字段并回填到右侧表单，支持 CRM 自动匹配、AI 创建客户/联系人、编码自动转换、线索分级建议等。

## 🏗️ 架构说明

原型是一份单文件 HTML（约 1700 行，全局函数 + 内联 onclick）。本工程在**逐行保真移植**的前提下做了分层：

1. **`core/` 纯函数层** — 抽取引擎与判定逻辑完全剥离 DOM，输入字符串、输出对象，便于穷举单测。这是 Demo 的「大脑」。
2. **`data/` 数据层** — 字段定义、编码表、CRM 库、示例样本，集中且可复用；运行时共享同一引用（CRM 库 / 导入数据会被动态增删）。
3. **`ui/` 视图层** — 每个功能区一个模块，内部用 `import` 互相调用；ES Module 的**实时绑定**天然支持模块间循环引用（所有调用都发生在运行时事件回调里，模块加载期无副作用）。
4. **`state.js` 状态层** — 把原型里会被「重新赋值」的全局量（如字段卡容器 `C`）集中到一个对象，保证跨模块看到同一份引用。
5. **`main.js` 装配层** — 绑定容器、把动态 HTML 里 `onclick="fn()"` 依赖的函数暴露到 `window`、接管静态模板的 `[data-action]` 按钮、启动面板。

> 抽取引擎、字段定义、示例数据均与原型**逐字对齐**，行为一致。

## 🤖 升级版：手搓 AI Agent（接真实大模型）

> 原型/POC 的"AI"是**前端规则引擎**（正则 + 关键词 + 编码表）模拟的 —— 确定、离线、零成本，但不会推理、换种说法就失效。
> 这一版把"假大脑"换成**真·大模型**，并 **100% 保留**原有全部交互与示例。两套大脑共存，真·AI 失败时自动回落规则引擎。

**什么是"手搓 agent"**：不依赖 LangChain / Dify / Coze 这类框架，自己手写这套循环 ——

```
用户说话 / 当前表单状态  →  [LLM 思考]  →  调用工具(fill_lead_fields / get_form_state / save_lead)
        ▲                                                │
        └─────────────  观察工具结果，决定下一步  ◀────────┘   （循环，直到给出回话）
```

模型只负责"决定做什么"，工具负责"真的去操作右侧字段卡 / CRM / 保存"，两者解耦 —— 这就是 agent 的本质。

**新增文件**（其余文件原样保留，未改动行为）：

```
src/agent/
├─ agentConfig.js    真·AI 总开关 + 代理地址 / 模型（localStorage 可覆盖）
├─ llmClient.js      只跟自家 Worker 对话（OpenAI 形状 messages + tools）
├─ tools.js          工具定义 + 执行器（填字段 / 读状态 / 保存；含下拉容错与编码徽标）
├─ systemPrompt.js   用"活数据"(字段/下拉/必填/编码/分级/CRM)动态拼提示词，永不漂移
├─ agentLoop.js      感知→思考→行动→观察 主循环 + 失败兜底回落规则引擎
└─ settingsModal.js  顶部状态徽标 +「AI 设置」面板
worker-llm/          LLM 代理（Cloudflare Worker）：替前端保管密钥、解决 CORS、支持多厂商
```

**怎么开启真·AI（给客户分发也是这套）**

1. 部署 LLM 代理：见 [`worker-llm/README.md`](worker-llm/README.md)（`npx wrangler secret put LLM_API_KEY` + `npx wrangler deploy`，约 3 分钟）。
2. 把 Worker 地址告诉前端，二选一：
   - **演示最快**：页面右上角点状态徽标 →「AI 设置」→ 粘贴地址 → 保存（存你这台浏览器）。
   - **分发给客户**：填进 `src/agent/agentConfig.js` 的 `BUILT_IN_LLM_PROXY_URL`，再 `npm run build`，把 `dist/` 交给客户 —— **打开即真·AI、零配置**。
3. 默认模型 **DeepSeek**（中文强、便宜）；在 Worker 端可一键换 Claude / OpenAI / 通义 / Kimi / 智谱。

**为什么这么设计**（对应 AI Agent 方法论第 ④ 条「失败兜底」）：密钥只在 Worker、前端永不持有；大模型超时 / 报错 / 超预算时静默回落本地规则引擎，**给客户演示永远不会"开天窗"**。未配置代理地址时（如本仓库默认、或跑单测时）自动就是规则引擎模式 —— 确定、离线、零成本。

> ⚠️ **成本提醒**：把公开 Demo 开放给"任何人"用 = 谁拿到链接都在消耗你的 token。建议用便宜模型，并在 `worker-llm` 里开启 `ALLOW_ORIGIN` 来源白名单或 `APP_TOKEN` 令牌（见其 README）。密钥在你手里，随时可在厂商后台轮换 / 停用。

## 📚 知识库 (RAG)

录线索时，Agent 会先**检索知识库**（公司产品 / 方案 / 案例 / 销售政策），把命中的片段注入提示词，让大模型"有据可依"地补全「产品分类 / 线索描述」、判断级别、或回答客户"你们有没有适合 XX 的方案"。对话区会显示"已参考知识库 N 条"（透明可解释，不做黑盒）。

- **检索方式**：浏览器内手写「关键词 / 双字匹配」检索（`src/agent/knowledge.js`），零成本、离线、确定。
  - 实测发现：Cloudflare Workers AI 的免费中文向量模型 **bge-m3 在短句上区分度极差**（不相关闲聊的余弦相似度反而更高，各条都挤在 0.88–0.99），故默认不用向量检索。Worker 仍保留 `/embed` 路由，将来要接更强的**付费** embedding（通义 / 智谱 / OpenAI）可平滑切换。
- **预置语料**：`src/data/knowledge.js`（16 条，与现有 demo 数据呼应），可整段替换成客户真实资料。
- **上传自己的文档**：对话框「+」菜单 →「知识库 (RAG) · 管理 / 上传」→ 上传 txt/pdf/word，自动切块入库；面板内可「试检索」一句话直观看到命中片段，也可删除已上传来源。
- 上传内容仅存当前浏览器（localStorage），刷新后预置语料仍在、上传内容保留在本机。

## 📌 说明

- 本项目有**两套大脑**：① 前端规则引擎（正则 + 关键词 + 编码表）—— 默认 / 离线 / 零成本 / 确定；② 接真实大模型的**手搓 Agent**（见上文「🤖 升级版」）。**未配置 LLM 代理时自动用 ①**，开箱即跑、完全离线可用（含图标）。这正是为「随时给客户演示、确定性、零成本、不依赖网络」而保留的取舍。
- 真·AI 的接入点正是当初预留的位置：`src/ui/chat.js` 的发送入口分流到 `src/agent/`（规则引擎 `smartExtract` 作为兜底完整保留），UI 与字段定义无需改动。生产使用建议再接后端做线索持久化。
- 「上传文件 / OCR / 语音」为交互演示：用预置样本模拟识别结果，体现产品流程而非真实文件解析。
- 涉及保存/导入的数据仅存于当前浏览器会话内存，刷新即清空。
